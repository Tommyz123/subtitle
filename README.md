# 实时语音翻译字幕系统

一个功能强大的桌面工具，可实时捕获系统音频，将其转录为文字，并翻译成您选择的语言，以现代化的悬浮窗样式显示双语字幕。

## 功能特性

### 核心功能
- **音频捕获与语音检测 (VAD)**:
  - 支持使用 `VB-Cable` 等虚拟音频设备捕获系统声音。
  - 内置 Silero VAD 语音活动检测，有效过滤静默片段，降低处理成本和干扰。
- **多种转录与翻译模式**:
  - **在线 API 模式**: 调用 OpenAI Whisper 和 DeepL 的云服务，提供高质量的转录和翻译。
  - **本地离线模式**: 在您自己的电脑上运行 `faster-whisper` 模型进行转录，并通过 `NLLB` 模型进行翻译，保护数据隐私，无额外费用。
- **Netflix 风格桌面字幕**:
  - 显示在所有窗口之上的透明悬浮窗。
  - 支持淡入淡出动画、拖动、缩放和样式设置。
  - 可同时显示原文和译文。
- **现代化 GUI**:
  - 简洁美观的 Material Design 风格界面。
  - 轻松选择源语言和目标语言。
  - 一键控制开始、停止和导出。
- **字幕导出**:
  - 所有字幕记录都可导出为标准的 `.srt` 文件，方便后续使用。

## 运行模式

本应用支持两种核心运行模式，您可以在程序主界面的“转录模式”中随时切换。

### 1. API 模式 (在线)
此模式利用云服务进行处理，效果最好，但需要稳定的网络连接和 API Keys。
- **转录**: OpenAI Whisper API
- **翻译**: DeepL API
- **优点**:
  - 通常拥有最高的准确率。
  - 对本地硬件要求低。
- **缺点**:
  - 需要支付 API 调用费用。
  - 依赖网络连接，延迟可能较高。
  - 隐私性较低，音频数据需要上传至云端。

### 2. 本地模式 (离线)
此模式在您的个人电脑上本地运行开源模型，无需联网，保护您的数据隐私。
- **转录**: `faster-whisper` (Whisper 的高效 CTranslate2 实现)
- **翻译**: Facebook NLLB (可选, 默认开启)
- **优点**:
  - **完全免费**: 无 API 费用。
  - **保护隐私**: 所有数据均在本地处理。
  - **低延迟**: 无需网络传输，响应更快。
- **缺点**:
  - 对硬件要求较高（特别是转录），推荐使用 NVIDIA 显卡 (GPU) 以获得最佳性能。
  - 准确率可能略低于 OpenAI 的最新 API 模型。
  - 首次运行时需要下载模型文件。

## 快速开始

### 1. 前置要求
- **操作系统**: Windows 10/11
- **Python**: 3.9+
- **虚拟音频设备**: [VB-Cable](https://vb-audio.com/Cable/)
  - 安装后**必须重启电脑**。
  - 将系统主音频输出设备设置为 `CABLE Input`，这样本程序才能捕获到声音。

### 2. 安装
克隆项目后，进入项目目录并安装所有依赖：
```bash
pip install -r requirements.txt
```
> **注意**: `requirements.txt` 会同时安装 API 模式和本地模式所需的所有库。如果您确认只使用一种模式，可以自行删减。

### 3. 配置 (.env 文件)
在项目根目录中，复制 `.env.example` 并重命名为 `.env`。然后根据您计划使用的模式编辑该文件：

```bash
copy .env.example .env
```

**配置说明:**

```env
# ======== 在线 API 模式配置 ========
# 如果您使用 API 模式，必须提供 OpenAI Key
OPENAI_API_KEY=sk-your-openai-api-key-here

# ======== 翻译配置 ========
# 默认情况下，本地模式使用免费的本地翻译。
# 如果您想在本地模式下强制使用 DeepL API，或者在 API 模式下进行翻译，请提供 DeepL Key。
DEEPL_API_KEY=your-deepl-api-key-here

# ======== 本地模式配置 ========
# 设置为 "true" 可在本地模式下使用免费的 NLLB 模型进行翻译，无需 DeepL Key。
# 设置为 "false" 则在本地模式下依然使用 DeepL API 进行翻译。
USE_LOCAL_TRANSLATION=true

# ======== 高级音频配置 ========
# 是否启用 VAD (语音活动检测)，可过滤无声片段，强烈建议保持 "true"
ENABLE_VAD=true

# 是否在程序内部播放捕获到的音频，用于调试。
# 警告：如果同时开启了系统的"侦听此设备"，可能会产生回音。
ENABLE_PLAYBACK=false
```

### 4. 运行程序
```bash
python app/main.py
```

## 使用说明

1. **选择运行模式**: 在 "转录模式" 中选择 `API (在线)` 或 `本地 (离线)`。
2. **配置模式选项**:
   - 如果选择 **本地模式**，您可以进一步选择：
     - **模型大小**: `base` 在速度和精度之间取得了很好的平衡。如果您的硬件性能强劲，可以尝试 `small` 或 `medium`。
     - **速度模式**: `balanced` 是一个安全的选择。`fast` 延迟更低但可能牺牲准确性。
     - **流式处理**: 勾选此项可实现更低的延迟，字幕会逐字或逐句出现，而不是等待一整段话结束后才显示。
3. **选择语言**: 在下拉菜单中选择**源语言**（您听到的语言）和**目标语言**（您想看的语言）。
4. **开始/停止**: 点击 `▶ 开始捕获` 启动程序。完成后点击 `⏹ 停止`。
5. **桌面字幕**: 勾选 `显示桌面悬浮字幕` 即可在屏幕上看到 Netflix 风格的字幕。
   - **拖动**: 按住 `Ctrl` + 鼠标左键
   - **缩放**: `Ctrl` + 鼠标滚轮
   - **设置**: 右键单击字幕窗口
6. **导出**: 点击 `💾 导出 SRT` 将当前会话的字幕保存为 `.srt` 文件。

## 技术架构
- **GUI**: `Tkinter`，搭配自定义的现代化组件。
- **多线程模型**:
  - **主线程**: GUI 事件循环。
  - **音频捕获线程**: 持续捕获音频，执行 VAD，然后将音频块放入队列。
  - **转录翻译线程**: 从队列中取出音频块，根据所选模式分派给相应的处理程序（本地或 API），然后将结果发回主线程更新 UI。
- **数据流**:
  `系统音频 → 音频捕获线程 → 音频队列 → 转录翻译线程 → GUI 回调 → 字幕UI & 字幕存储`

## 常见问题 (FAQ)

- **Q: 为什么程序没有声音了？**
  - **A:** 因为您已将系统音频输出重定向到 `VB-Cable`。如果您想同时听到声音，请在 Windows 的声音设置中，找到 `CABLE Output` 设备的属性，切换到“侦听”标签页，然后勾选“侦听此设备”并选择您的扬声器或耳机。

- **Q: 提示 "未找到 VB-Cable 设备"？**
  - **A:** 请确保您已正确安装 VB-Cable 并且**重启了电脑**。

- **Q: API 模式提示 "配置错误"？**
  - **A:** 请检查您的 `.env` 文件是否已正确填写 `OPENAI_API_KEY` 或 `DEEPL_API_KEY`。

- **Q: 本地模式第一次运行很慢？**
  - **A:** 首次在本地模式下运行某个模型时，程序需要从 HuggingFace Hub 下载该模型文件。这可能需要一些时间，具体取决于您的网络速度和模型大小。下载完成后，后续启动会非常快。
