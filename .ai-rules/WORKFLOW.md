# 开发工作流程

## 📋 概述

本文档定义 Claude Code 的标准开发工作流程，确保每个阶段的实施都遵循统一的规范。

---

## 🚀 Claude Code 工作流程

### 阶段启动流程

1. **读取入口文件**
   - 读取根目录 `claude.md` 了解当前状态和任务
   - 确认当前处于哪个阶段

2. **读取项目概览**
   - 读取 `.ai-rules/README.md` 了解项目详情
   - 查看项目进度追踪，确认已完成和待完成任务

3. **读取实施指南**
   - 读取 `.ai-rules/implementation-roadmap.md`
   - 找到当前阶段的详细任务清单和验收标准

4. **读取模块设计**
   - 根据当前任务，读取相关的 `modules/*.md` 文件
   - 理解每个模块的职责、类设计和关键方法

5. **读取技术指南**
   - 读取 `technical/critical-fixes.md` 了解必须避免的错误
   - 根据需要读取其他技术专题（threading, vad-optimization）

6. **开始实施**
   - 创建或编辑相应的代码文件
   - 严格遵循模块设计文档中的规范
   - 应用所有相关的P0级别修复

7. **更新项目状态**
   - 完成任务后，更新 `claude.md` 中的项目进度
   - 更新 `.ai-rules/README.md` 中的进度追踪
   - 标记已完成的任务

---

## 📊 每个阶段的标准流程

### 阶段1：基础MVP版本

#### 实施顺序
```
1. app/subtitle_storage.py      # 最简单，无依赖
   ↓
2. app/audio_capture.py          # 仅依赖Queue
   ↓
3. app/transcription.py          # 依赖API客户端
   ↓
4. app/main.py                   # 整合所有模块
```

#### 每个文件的实施步骤
1. 创建文件，导入必要的库
2. 定义类和 `__init__` 方法
3. 实现核心方法（按照 modules/*.md 的顺序）
4. 添加必要的错误处理
5. 应用相关的P0修复
6. 添加基本的调试日志（print语句）

#### 验收步骤
1. **功能测试**
   - 运行 `python app/main.py`
   - 点击"开始捕获"，播放测试视频
   - 确认字幕正确显示
   - 点击"导出SRT"，检查文件格式

2. **问题检查**
   - 检查是否应用了阶段1的6个P0修复
   - 运行30分钟，检查内存是否稳定
   - 检查停止按钮是否正常工作

3. **更新状态**
   - 在 `claude.md` 标记阶段1完成
   - 在 `README.md` 勾选所有阶段1任务

4. **请求用户确认**
   - 向用户展示测试结果
   - 获得确认后进入阶段2

---

### 阶段2：优化版本

#### 实施顺序
```
1. app/silero_vad_iterator.py   # 新增VAD实现
   ↓
2. 更新 app/audio_capture.py    # 集成VAD
   ↓
3. 更新 app/transcription.py    # 添加重试+VAD跳过
   ↓
4. 更新 app/main.py             # 配置验证+锁
```

#### 关键修复应用
在这个阶段，必须应用所有12个P0修复：
- 阶段1已应用的6个
- 阶段2新增的6个（VAD相关）

#### 验收步骤
1. **功能测试**
   - 运行程序，确认VAD模型成功加载
   - 播放测试视频，查看日志中的"[VAD] 跳过静音段"
   - 确认API失败自动重试

2. **性能测试**
   - 查看统计信息，确认节省比例30-50%
   - 运行1小时，检查内存是否稳定
   - 测试停止响应时间（应 < 15秒）

3. **更新状态**
   - 在 `claude.md` 标记阶段2完成
   - 在 `README.md` 勾选所有阶段2任务

4. **请求用户确认**
   - 展示成本节省统计
   - 确认后可选进入阶段3

---

## ⚠️ 关键注意事项

### 开发过程中

1. **严格遵循设计文档**
   - 类名、方法名必须与文档一致
   - 参数类型和返回值必须符合规范
   - 不要自行发挥，添加未计划的功能

2. **应用所有P0修复**
   - 每实现一个模块，检查 `critical-fixes.md`
   - 确保应用了所有相关的修复
   - 特别注意：Queue maxsize、Lock保护、scipy重采样

3. **保持代码简洁**
   - 阶段1不实现阶段2的功能
   - 避免过度设计
   - 先让功能跑起来，再优化

4. **及时更新文档**
   - 完成任务后立即更新 `claude.md`
   - 勾选 `README.md` 中的进度
   - 保持文档与代码同步

---

### 验收过程中

1. **功能完整性**
   - 所有计划的功能都已实现
   - 验收标准全部通过
   - 无明显Bug

2. **代码质量**
   - 应用了所有相关的P0修复
   - 代码结构清晰，易于理解
   - 有必要的错误处理和日志

3. **用户体验**
   - 界面响应流畅
   - 错误提示清晰
   - 功能符合预期

---

## 🔄 问题处理流程

### 遇到技术问题

1. **查阅相关文档**
   - 先查 `technical/critical-fixes.md`（是否是已知问题）
   - 再查相关的技术专题文档
   - 最后查阅原始 `plan.md`

2. **尝试解决**
   - 应用文档中的解决方案
   - 添加调试日志定位问题
   - 参考 `example/WhisperLiveKit-main/` 代码

3. **请求用户帮助**
   - 如果问题无法解决，向用户说明情况
   - 提供详细的错误信息和已尝试的方案
   - 询问用户是否有额外信息或建议

---

### 需求变更

1. **评估影响**
   - 变更影响哪些模块？
   - 是否需要修改架构设计？
   - 是否影响其他阶段的计划？

2. **更新文档**
   - 先更新相关的 `.ai-rules/*.md` 文档
   - 然后更新代码
   - 保持文档和代码一致

3. **重新验收**
   - 变更后重新执行验收流程
   - 确保没有引入新问题
